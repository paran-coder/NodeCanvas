# HairLock v1.0.1 — Private workflow

## Mission and success criteria

Use the **uploaded original image as the actual identity reference**, never a JSON-only recreation. Change the requested hairstyle while preserving the person's perceived identity. The image is acceptable when a typical viewer would recognize the same person, and structural changes to the **eyes, nose, mouth, facial proportions, and jaw** are not noticeable. Lighting, skin tone/texture micro-changes, hairline, and hair-cast shadows may vary naturally. Pixel-for-pixel facial equivalence is **not** a default goal.

## User experience: return image, hide evaluation

- The default user flow is: uploaded portrait + user hairstyle instruction -> hairstyle edit -> best acceptable final image. Present the final image only, with a brief neutral explanation only when needed.
- Perform any available identity/quality assessments **internally**. Do **not** routinely display similarity scores, landmark shifts, candidate rankings, internal JSON, mask debug views, retry counts, or quality logs. If the user explicitly requests a technical diagnostic report, explain what was actually checked, without invented measurements.
- Do not make the user choose from candidate images unless explicitly requested; prefer selecting the best acceptable result internally when such candidate/assessment tools actually exist.
- Do not advertise a verified result or scoring system when it did not run.

## Hairstyle edit workflow

1. Read the uploaded original image and the requested haircut, length, texture, part, bangs, and color. Preserve unspecified features. Prioritize a single centered, near-frontal realistic face for the MVP; angled and multiple-person portraits remain experimental.
2. When native image editing is available and the user asks for an edit, **invoke it** using the original image. Prompt for the requested hairstyle only; preserve eye shape/position, eyebrows, nose bridge/tip/width, mouth/lips, expression, jaw/face proportions, camera angle, background, and clothing. Allow natural hairstyle-specific occlusion and shadows.
3. Review the produced image visually against the original if both can be inspected. Prioritize structural eye/nose/mouth consistency, recognizable identity, hair realism, and no accidental clothing/background distortions. Do not equate non-identical pixels with a different identity.
4. If the result visibly changes facial features and retry capability exists, retry from **the original source image**, with stricter facial preservation instructions. Limit retries; do not repeatedly compound edits on earlier edited results.
5. If candidate generation and comparison are actually available, choose the most natural candidate that passes the perceptual identity test. If not available, use a single best-effort candidate rather than claiming an invisible multi-candidate quality gate.
6. If repeated attempts visibly fail, use optional regional masking/partial original-face recomposition **only when a connected tool truly supports it**. If this is unavailable, transparently explain that a faithful result could not be produced; do not claim an inaccessible backend was used.
7. Return only the accepted final image by default. Do not show the assessment details.

## JSON behavior (on request only)

- JSON is a **control specification**, not enough to reconstruct a unique face. Use the original image as source.
- Include `identity_source`, `hairstyle`, `protected_features`, `editable_regions`, `allow_shadows`, `quality_target`, and `evaluation_visibility` as needed. Do not invent pixel-precise landmarks, masks, scores, or evidence of verification.
- Do not generate JSON as a mandatory visible output during ordinary hairstyle edits; keep it internal if possible.

Example:

```json
{
  "version": "1.0.1",
  "identity_source": "original_user_image",
  "hairstyle": {"instruction": "USER_REQUEST"},
  "protected_features": ["eyes", "eyebrows", "nose", "mouth", "face_proportions", "jawline"],
  "editable_regions": ["existing_hair", "scalp", "hairline", "hair_volume"],
  "allow_shadows": true,
  "quality_target": "same_person_no_noticeable_facial_feature_changes",
  "evaluation_visibility": "internal_only",
  "landmark_coordinates": null,
  "mask_source": null,
  "evaluation_performed": false
}
```

## Installed capabilities and safety limits

- This private plugin release is a **chat skill**, not a deployed MCP image-processing service. The separate Python backend is **not automatically connected**; optional pixel-protective compositing requires a real connected tool/server.
- Native image generation/editing may produce perceptually similar faces but cannot guarantee 100% matching facial pixels. Do not promise otherwise.
- A request for a hairstyle edit must produce an edited image when an editing tool is available; do not output only a prompt instead.
- Protect the user's privacy; never reveal API keys, full image contents, internal quality logs, or sensitive face embeddings. Respect image rights.

# NodeCanvas v1.9.0 검증 — 2026-11-01

## 구현
- 업데이트 기능을 처음 도입. 기존 v1.8.2 보존.
- 네이티브 연결 앱 시작 시와 6시간마다 자동 확인/다운로드. 웹에서는 준비 알림과 지금 적용 버튼.
- RSA-SHA256 서명 매니페스트, 고정 HTTPS 서버/파일 이름, 파일 크기/해시 확인. 리디렉션·외부 URL·다운그레이드 거부.
- 적용 직전 캐시 재검증. origin 및 페어링 필수. 생성/로그인/적용 중 상호 배제.
- 새 버전 디렉터리에 준비하고 기존 앱 종료 후 시작 확인. 실패 시 이전 앱 재시작 및 변경된 등록 복구 코드.
- 작업 브라우저 새 challenge로 자동 재연결. 저장된 로그인 선호·사용자 데이터 경로 유지. 임시 로그인은 재시작 시 해제.
- 최초 v1.9.0 설치는 수동. 이 버전부터 미래 서명된 릴리스를 자동 다운로드.

## 검증
- Node 단위/통합 회귀 88/88 통과.
- 실제 웹 앱 headless Chromium: PC/모바일, 준비 상태·적용 challenge·새 토큰 재연결·화면 overflow 및 JS 오류 없음. 네이티브/API 응답은 모의.
- 실제 C# 설치 앱: workspace 격리된 경로에서 prepare, 적용 전 실패 복구, 적용 후 실패 복구, 잘못된 활성화 요청 거부, 별도 사용자 데이터 보존 PASS.
- 네이티브 검사에서 실제 사용자 설치·레지스트리·계정은 수정하지 않음. 실제 설치 전체 재시작/레지스트리 복구와 Vercel HTTPS 업데이트 흐름은 미검증.
- 자체 평가: 설계 8/10, 구현/격리 검증 8.5/10. 실제 PC 버전 간 업데이트 수용 테스트가 남음.

## 서명키
비밀키는 프로젝트 루트 .runtime/2026-11-01-update-signing/private.pem에만 존재하고 배포 ZIP에서 제외합니다. 이 폴더는 임시 파일로 정리하지 말고 별도 안전한 위치에 백업해야 합니다. 다음 버전에도 같은 키를 사용해야 기존 앱이 검증할 수 있습니다. 새 키로 교체하면 기존 앱 업데이트 신뢰 경로도 별도로 이전해야 합니다.

## 운영
- 배포 파일을 직접 업로드하며 여기서는 GitHub/배포를 실행하지 않음.
- 설치 앱은 Windows 코드 서명(Authenticode) 인증서로 서명된 것은 아님. 업데이트 매니페스트의 RSA 서명은 별도 검증 수단.
- 기존 루트 문서 4개/설정은 유지. GitHub 폴더에 새 버전용 문서/설정을 제공.
